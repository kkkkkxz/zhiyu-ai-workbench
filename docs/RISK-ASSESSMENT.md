## 二、高风险项（上线前必须处理）

### R1 · 生成式 AI 合规

**法规依据**

- 《生成式人工智能服务管理暂行办法》（2023.8.15 施行，国家网信办等七部门）
- 《互联网信息服务深度合成管理规定》（2023.1.10 施行）

**触发条件**

你的系统提供了**基于 AI 的文本生成（RAG 问答）和语音合成（TTS）**，属于"生成式人工智能服务"和"深度合成服务"的管辖范围。

**需要做的事**

| 序号 | 事项 | 负责人 | 状态 | 说明 |
|------|------|--------|------|------|
| 1 | 算法备案 | 你 | 待办 | 在"互联网信息服务算法备案系统"(https://beian.cac.gov.cn) 提交。你用的是阿里云百炼（DashScope）底层模型，阿里云已有模型备案，但你的**应用层算法**（RAG 检索+提示词组合）如果构成独立的"生成合成类"或"个性化推送类"算法，需要独立备案。建议咨询阿里云百炼客服确认：你的场景属于"直接使用已备案模型"还是需要自备。 |
| 2 | AI 生成内容标识 | 已部分满足 | 待确认 | 深度合成规定要求 AI 生成的文本、语音必须进行显著标识。当前系统通过 SSE 返回文本，前端渲染，需要确认：聊天界面是否标注了"AI 生成内容"提示语？如未标注，需在 ChatPage 消息气泡上加一行小字。 |
| 3 | 用户协议 + 隐私政策 | 待办 | 上线前 | 注册/登录页必须展示并强制同意《用户服务协议》和《隐私政策》，明确告知：①使用了 AI 生成技术；②用户的输入和输出数据可能用于改进服务；③用户不得输入违法违规内容。 |
| 4 | 用户实名 | 已部分满足 | 待评估 | 法规要求提供"与使用者信用匹配的实名认证"。当前仅有用户名+密码注册，如果面向公众开放，可能需要手机号验证。如果仅面向企业内部用户（每个企业有管理员邀请制），当前机制基本够用。 |

**缓释措施**

- 第一阶段（香港 ECS + 内部客户）：风险较低，因为你是"向特定企业客户提供生产力工具"，不是"向公众开放的生成式 AI 服务"
- 第一时间在注册页加用户协议和隐私政策
- 在 AI 回复气泡上标注"AI 生成内容，仅供参考"
- 咨询阿里云百炼关于算法备案的适用性
- 如果将来面向 C 端公众开放，必须完成算法备案

### R2 · 数据安全与个人信息保护

**法规依据**

- 《数据安全法》（2021.9.1 施行）
- 《个人信息保护法》（2021.11.1 施行）
- 《数据出境安全评估办法》（2022.9.1 施行）：数据出境到香港可能触发

**系统存储的敏感数据**

| 数据类型 | 存储位置 | 敏感程度 |
|----------|----------|----------|
| 用户密码（BCrypt） | MySQL sys_user | 中 |
| 用户手机号/邮箱 | MySQL sys_user | 高 |
| AI 对话历史 | MySQL ai_session / ai_message | 中 |
| 知识库文档内容 | MySQL + MinIO + Qdrant | 中-高（取决于企业上传了什么） |
| 审计日志 | MySQL audit_log | 低 |
| JWT Token | Redis | 中 |

**需要做的事**

| 序号 | 事项 | 状态 | 说明 |
|------|------|------|------|
| 1 | 隐私政策 | 待办 | 必须在注册页展示。内容包括：收集哪些数据、用途、存储期限、用户权利（查看/删除/导出）、联系方式。 |
| 2 | 数据删除机制 | 已部分满足 | 系统有逻辑删除，但需要确认用户注销账号时是否会物理删除或匿名化历史对话数据。 |
| 3 | 数据加密 | 已满足 | 传输层 HTTPS + 数据库密码 BCrypt，密码强度达标。 |
| 4 | 数据出境合规 | 待评估 | 香港 ECS 属于"数据出境"。如果客户是中国大陆企业、知识库文档含商业秘密/个人信息，则触发《数据出境安全评估办法》。**短期缓释**：香港节点仅服务你自己或少数测试用户；长期**必须**迁回大陆 ECS。 |
| 5 | 最小权限原则 | 已满足 | 多租户 + RBAC + 数据权限，SQL 拦截器做租户隔离。 |

**数据出境最关键的约束**：如果你的客户是中国大陆企业，把他们的内部文档上传到香港服务器存储和处理，严格来说属于"数据出境"。建议：
- 香港 ECS 仅用备案通过前的过渡期
- 过渡期不上传真实客户数据
- 备案通过后立刻迁回大陆 ECS

### R3 · AI 内容安全

**现有防线（项目已具备）**

你的项目已经有内容安全模块（`com.zwskchat.zwskchat.safety`），包括：

1. **关键词+正则过滤**（`KeywordContentSafetyService`）：默认启用，零延迟，配置在 `application.yaml` 的 `zwsk.content-safety.banned-words` / `banned-patterns`
2. **模型审核**（`ModelContentSafetyService`）：调用 LLM 做语义级别的内容分类，可单独使用或与关键词配合
3. **高风险话题守卫**（`HighRiskSlotDetector`）：对敏感领域检测并拒绝回答
4. **回答输出合约**（`ResponseGovernanceService`）：校验 AI 输出不包含不安全内容

当前配置（`ContentSafetyProperties` 第 31 行 `mode = "keyword"`）仅启用关键词过滤。

**需要做的事**

| 序号 | 事项 | 状态 |
|------|------|------|
| 1 | 生产环境内容安全（`mode` 建议设 `both`，先过关键词再过模型审核，双重防线，成本低、安全上限更高） | 待改 |
| 2 | 补充违禁词列表，覆盖政治敏感、色情、暴力、违法犯罪等类别 | 待办 |
| 3 | 配置告警：命中审核时触发 WARN 日志 → 接入钉钉/飞书/企业微信通知 | 建议 |
| 4 | 定期人工抽检 AI 对话日志，复核误杀和漏杀 | 持续 |

## 三、中风险项

### R4 · ICP 备案与香港节点过渡

**风险**：香港 ECS 是国内备案通过前的短期方案。大陆用户访问香港节点的延迟高、跨境线路不稳定。

**预案**：
- 备案通过后，决定是继续用香港（简单但慢）还是迁回大陆（快但需要迁移）。
- 如果迁回大陆，准备好数据库备份恢复流程（项目已有 `backup-mysql.sh`），迁移窗口约 1-2 小时。

### R5 · 知识产权（知识库版权）

**风险**：用户上传到知识库的文档可能包含他人版权内容（PDF 书籍、商业报告、代码等），如果 AI 直接复述原文，可能构成侵权。

**缓释措施**：
- 用户协议中写清楚"上传者保证拥有合法权利，平台不承担侵权责任"
- RAG 的 top-k 检索 + 重排机制本身会混合多个来源，降低了逐字复述的概率
- 提供 DMCA/侵权投诉渠道（一个联系邮箱即可）

### R6 · 开源许可证

你的项目依赖了大量开源组件。主要检查：

| 依赖 | 许可证 | 风险 |
|------|--------|------|
| Spring Boot | Apache 2.0 | 无 |
| MyBatis-Plus | Apache 2.0 | 无 |
| MySQL Connector/J | GPL 2.0 | **低风险**：仅作为驱动连接，不修改 MySQL 源码，不属于"衍生作品"，不被 GPL 传染。但如果担心，可换 MariaDB Connector (LGPL) |
| Redis/Lettuce | Apache 2.0 | 无 |
| Tika | Apache 2.0 | 无 |
| Hutool | 木兰宽 / Apache | 无 |

结论：没有阻塞级别的许可证问题。GPL MySQL Connector 是驱动级使用，法律上通常不认定为衍生作品。如果不放心，可以记录未来评估 MariaDB Connector 替换。

### R7 · 阿里云百炼 API 依赖

**风险**：你的 AI 对话、向量化、语音 ASR/TTS 全部依赖阿里云百炼 DashScope。如果阿里云：
- 调整百炼 API 价格（已有调价先例）
- 下线或变更 API
- 账号被限流/封禁

**缓释措施**：
- 代码已有 `AiProvider` 抽象层（`ai/provider`），可以接入备用模型（OpenAI / 开源模型）
- 短期不致命，但长期建议在文档里注明至少一个备用方案
- 关注百炼控制台的余额和限流告警

## 四、低风险项

### R8 · 服务器安全

项目已有的安全措施：

- ✅ JWT + BCrypt + Redis Token 黑名单 + 强制下线
- ✅ RBAC + 数据权限 + 多租户 SQL 拦截
- ✅ 接口限流（Redis Lua 滑动窗口）
- ✅ 审计日志（AOP 关键操作记录）
- ✅ 日志脱敏（手机号/身份证/邮箱打码）
- ✅ CORS 白名单
- ✅ Nginx 安全头（HSTS、X-Content-Type-Options、X-Frame-Options、Referrer-Policy、Permissions-Policy）
- ✅ Docker 内网 bridge 网络，中间件不暴露公网端口
- ✅ `PRODUCTION-CHECKLIST.md` 安全要求
- ✅ `StartupSecurityCheck` 启动弱口令检测

建议补充的安全措施：

| 序号 | 事项 |
|------|------|
| 1 | ECS 上配置 fail2ban 防止 SSH 暴力破解 |
| 2 | 开启阿里云云安全中心（基础版免费） |
| 3 | 定期 `apt update && apt upgrade` |
| 4 | 用非 root 用户运行 Docker（`deploy.sh` 已有 `sudo usermod`） |

### R9 · 语音电信合规

**风险**：WebSocket 实时语音对话功能，如果面向公众开放

**评估**：当前语音功能仅在企业内部使用场景（客服助手、知识库问答），不走 PSTN 落地，不涉及公共电话网络。风险低。但如果未来加入电话接入，需要申请增值电信业务经营许可证（ICP 证 + 呼叫中心业务）。

## 六、最坏情况应急预案

| 场景 | 应对 |
|------|------|
| 收到网信办/监管部门通知整改 | 立即暂停公网服务，保留数据，配合整改 |
| 阿里云百炼 API 停服 | 48 小时内切换到备用模型（如 OpenAI 兼容接口），修改 `ai.provider.impl` 配置 |
| 服务器被入侵 | 安全组关闭所有公网端口 → 快照取证 → 重建 ECS + 恢复最新备份 |
| 用户数据泄露 | 24 小时内通知受影响用户 + 向监管部门报告（PIPL 第 57 条） |
| 知识产权侵权投诉 | 下架相关内容 → 通知上传用户 → 保留 15 天处理期 |
| 域名备案被拒/注销 | 迁到香港 ECS 继续提供服务，同时重新申请备案 |
